## Facts (from the paper, each with location: Sec./p./Table/Fig.)
- Task / problem: parameter-efficient continual learning of CLIP for image classification that limits forgetting of learned tasks and keeps CLIP's zero-shot transfer to unseen data, while avoiding the cost of full fine-tuning as in ZSCL (Abstract; Sec. 1, p. 1; Fig. 1).
- Data (Sec. 4.1, p. 6): (i) MTIL benchmark of ZSCL, 11 datasets (Aircraft, Caltech101, CIFAR100, DTD, EuroSAT, Flowers, Food, MNIST, OxfordPet, Cars, SUN397), Order I (left to right as in Table 1; main results) and Order II (Suppl. Tables 11–12); also a 5-shot MTIL variant (Table 2). (ii) Class-incremental CIFAR100 split into 10, 20 or 50 steps and TinyImageNet (100 base classes) split into 5, 10 or 20 steps, following DyTox (Sec. 4.1; Tables 3–4). Reference dataset for the out-of-distribution autoencoder: TinyImageNet (Sec. 4.1).
- Method (two sentences): CLIP ViT-B/16 is frozen and every transformer block of both encoders gets a mixture of LoRA experts (N_E = 22, not shared between encoders), combined by a task-specific router (one MLP per task, top-2 gating on the [CLS] token); after each task the top-k most activated experts are frozen, so later routers can reuse them while the remaining experts learn the new task ("incremental activate-freeze") (Sec. 3.3, Eq. 1–2, Fig. 2–3; Sec. 4.1). At inference a Distribution Discriminative Auto-Selector (DDAS), one autoencoder per task on AlexNet features trained with MSE reconstruction (Eq. 3), picks the router with the lowest reconstruction score, and if all scores exceed a threshold (0.065 full-shot, 0.06 few-shot) the input goes to the original frozen CLIP for zero-shot prediction (Sec. 3.4; Sec. 4.1). No exemplar memory; no distillation; trained parameters 59.8 M (MoE-Adapters 51.1 M + DDAS 8.7 M) vs 149.6 M for ZSCL (Table 5).
- Setting: MTIL = "Multi-domain Task Incremental Learning" in the paper's terms (Sec. 4.1), but the router is selected by DDAS, so task identity is not supplied at inference (Sec. 3.4; Fig. 2b "Task agnostic"). For CIL the model uses one router with two experts for all steps (Sec. 4.2, p. 7). Few-shot: 5-shot MTIL, 500 iterations per task (Table 2; Sec. 4.1). Training 1k iterations per task full-shot ("Ours"), 3k for the variant "Ours†" (Table 1 caption).
- Evaluation (Sec. 4.1, p. 6): MTIL metrics from ZSCL, in %: "Transfer" (zero-shot accuracy on not-yet-learned data), "Last" (accuracy after the final task, memorisation), "Average" (the paper describes it as "a composite metric measuring the mean performance across 'Transfer' and 'Last'"; ZSCL, whose metrics it says it adopts, defines Avg. as the mean over all time steps, paper_notes/zscl.md l. 46, so the paper's one-line description is loose; the zero-shot CLIP row 65.3 = ZSCL's 65.3 suggests ZSCL's definition is what is computed, but this is not stated). CIL: "Avg." (mean accuracy over all steps) and "Last" (after the last step). Upper references: per-task zero-shot, full fine-tuning and fine-tuned adapter (Table 1 top block). Baselines: Continual-FT, LwF, iCaRL, LwF-VR, WiSE-FT, ZSCL (MTIL); UCIR, BiC, PODNet, DER, DyTox(+), DNE, EWC, EEIL, MUC, PASS, CLIP zero-shot, fine-tune and the MTIL baselines (CIL).
- Best result: MTIL Order I, "Ours" (1k iterations): Transfer 68.9, Average 76.7, Last 85.0 vs ZSCL 68.1 / 75.4 / 83.6 (+0.8 / +1.3 / +1.4); "Ours†" (3k): 67.4 / 77.2 / 87.4 (Transfer −0.7 vs ZSCL) (Table 1, p. 5). 5-shot MTIL: 68.9 / 71.4 / 76.1, +3.6 / +7.0 / +4.2 over the second-best method (ZSCL 65.3 Transfer and 64.4 Average; WiSE-FT 71.9 Last) (Table 2, p. 6). CIFAR100 CIL 10 steps Avg. 85.21, Last 77.52 vs ZSCL 82.15 / 73.65 (Table 3, p. 7); TinyImageNet 5 steps 81.12 / 76.81 vs ZSCL 80.27 / 73.57 (Table 4). Training cost vs ZSCL: −60.03 % parameters, −14.95 % GPU memory (22358 vs 26290 MiB), −59.90 % time per iteration (Table 5). Ablation: 22 experts with 11 routers without the freeze strategy 68.6 / 75.1 / 82.0 (Table 6).
- Limitations stated by the authors (Sec. 5, p. 8): DDAS needs one predefined threshold for all tasks, which will cause errors as the number of tasks grows; using learned knowledge to improve CLIP's zero-shot ability is left to future work. Sec. 4.3 (p. 8, Fig. 5) reports that some Task 9 samples are wrongly classed as out-of-distribution by DDAS and sent to the reference branch.

## Relevance (NOT from the paper)
The only one of the three VLM papers with a few-shot (5-shot) continual setting; it shows routed LoRA experts with learned task selection, which this thesis avoids by giving task identity to task-specific LoRA and using a single shared adapter otherwise.
