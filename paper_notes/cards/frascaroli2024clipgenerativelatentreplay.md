## Facts (from the paper, each with location: Sec./p./Table/Fig.)
- Task / problem: class-incremental image classification with CLIP that adapts to domains far from the pre-training data (satellite, medical) while keeping zero-shot ability, without a buffer of real images (Abstract; Sec. 1, p. 2).
- Data (Sec. 5, pp. 6–7; Suppl. A): five benchmarks: Split ImageNet-R (200 classes, 10 tasks), Split Cars-196 (10 tasks: 9 × 20 classes + 16), Split CUB-200 (10 tasks), Split EuroSAT (5 binary tasks), Split ISIC (6 skin-disease classes, 3 tasks; most frequent class "Melanocytic nevus" removed). Images 224 × 224. Task order: class order set by three fixed seeds (1992, 1996, 1997), so task composition varies across seeds.
- Method (two sentences): CLIP ViT-L/14 visual and text encoders are frozen; for each class of the current task a lightweight VAE (three fully connected layers, hidden 512, latent 256) is trained on the CLIP visual embeddings, and only its decoder is kept in memory (Sec. 4.1, Fig. 1, Alg. 1; Sec. 5). After each task, about 15K synthetic embeddings per class are sampled from all stored decoders (past and current classes) and used to train the text-side prompt of each class, made of a class-specific learnable token plus a hyper-token generated by a shared MLP from the hand-crafted prompt embedding (Eq. 3–4); previously learned prompts keep being refined, and unseen classes use the hand-crafted prompt "a photo of a <CLS>" (Sec. 4.1; Sec. 5).
- Setting: class-incremental learning, task identity unknown at inference (Sec. 5, "Metrics"); disjoint classes per task (Sec. 4); no few-shot setting. The authors note it can be seen as online CL since each image passes the visual encoder once (Sec. 6.1).
- Evaluation (Sec. 5, Eq. 5): Final Average Accuracy (FAA, "Last Accuracy") = average accuracy over all tasks after the last task; Class Incremental Transfer (CI-Transfer, new metric adapted from ZSCL/MoE-Adapters) = mean CIL accuracy on tasks not yet trained. Results averaged over 3 seeds, standard deviations in Suppl. Table D. Baselines: zero-shot CLIP, LwF, GDumb, DER++, SLCA (full fine-tuning), L2P, DualPrompt, CODA-Prompt, AttriCLIP, ZSCL, MoE Adapters (Sec. 5; Table 1). Joint reference: CoOp (Joint) and CoOp (Fine-tune) (Sec. 6; Table 3).
- Best result: FAA average over the five benchmarks 86.20 vs best competitor SLCA 75.46, MoE Adapters 69.70, ZSCL 68.50, zero-shot CLIP 55.47; per benchmark Img-R 89.42, Cars 89.27, CUB 83.12, EuroSAT 96.17, ISIC 73.03 (Table 1, p. 7). CI-Transfer average 70.31 vs ZSCL 63.12, zero-shot CLIP 55.32 (Table 2, p. 8). CoOp (Joint) 86.29, CoOp (Fine-tune) 65.95 (Table 3, p. 9). CGIL std ±0.10 to ±0.14 except ISIC ±1.75 (Suppl. Table D).
- Limitations stated by the authors (Sec. 6.1, p. 10): one decoder per class (about half a million parameters, ~2 MB, comparable to 14 RGB images of 224 × 224), so memory grows with the number of classes, which "could restrict its applicability"; the prompt-alignment phase backpropagates through the CLIP text encoder and is the costly part of training. Decoders are needed only for training; inference is one visual-encoder pass plus a matrix product.

- related_work.tex:50 "Replay in this setting is reformulated to protect the shared multimodal embedding space under memory and privacy constraints, and recent methods replace stored images with synthesised data" → partly supported: CGIL motivates generative replay by data anonymity/privacy and avoiding a buffer of real examples (Sec. 1, p. 2); "protect the shared multimodal embedding space" is the author's framing, not CGIL's (CGIL keeps both encoders frozen, so the embedding space itself is not changed).
- related_work.tex:50 "CGIL trains lightweight per-class variational autoencoders on the embeddings of the frozen CLIP visual encoder, and samples synthetic embeddings from them to learn class-specific text prompts" → correct (Sec. 4.1; Alg. 1). Precise addition: the prompt also has a hyper-token from a shared MLP (Eq. 3–4), so it is not purely class-specific.
- related_work.tex:50 "at a storage cost that grows with the number of classes" → correct (Sec. 6.1, p. 10).
- related_work.tex:50 "In both cases the burden moves from storage to modelling: what is preserved is limited by how faithfully the latent or image generator represents the earlier data" → author's interpretation; partly supported by Table 3 (better generators give higher FAA: Gaussian 76.83 vs VAE 86.20, the paper says "the quality and variety of the generated data are crucial", p. 9).

## Relevance (NOT from the paper)
Frozen encoders plus generative latent replay with per-class generators; the per-class decoder scales with classes, and for 3D segmentation the analogue (per-structure latent generators of volumetric features) would be far heavier. Of note for this thesis: CGIL includes a medical benchmark (ISIC) where zero-shot CLIP is weak (26.59).
