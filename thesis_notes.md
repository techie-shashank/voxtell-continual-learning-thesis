**Method fact sheet (read from `code/` and run configs/logs, 2026-10-21)** — for Ch. 5
- *Model as used.* VoxTell v1.1: ResEnc UNet image encoder; prompt decoder = 6 transformer decoder layers, 8 heads, d = 2048, pre-norm (`model/voxtell_model.py:35-36,192-201`); its memory (keys/values) is encoder stage 4 (320 channels, 12³ for a 192³ patch, `decoder_layer=4` in `model/builder.py:59`), **not** the 6³ bottleneck the paper's Eq. 3 suggests; text-guidance channels per stage G = 32 (`num_heads=32`); fusion at 5 decoder stages; text embedding dim 2560. Text encoder Qwen3-Embedding-4B, frozen (`@torch.no_grad`), instruction prefix "Instruct: Given an anatomical term query, retrieve the precise anatomical entity and location it represents\nQuery: <prompt>" (`text/encoder.py`, `utils/text_embedding.py:14-20`). Deep supervision off in all runs (config), so the loss uses the full-resolution output only.
- *Prompt-decoder layer as executed* (verified 2026-10-21, `model/voxtell_model.py:191-201`, `model/transformer.py:224-265, 355-363`): `TransformerDecoderLayer(normalize_before=True)` -> `forward` dispatches to **`forward_pre`**; `forward_post` and `forward_pre_selfattention` are never called. `forward_pre` = LN (`norm2`) -> **cross-attention** (`multihead_attn`; query = normalised text query, `query_pos` = None; key = stage-4 features + positional encoding; value = stage-4 features **without** positional encoding) -> residual; LN (`norm3`) -> FFN (Linear d->2048, ReLU, dropout 0.1, Linear 2048->d) -> residual. **No self-attention is applied**: `self_attn` and `norm1` exist in every layer but are unused. A final LayerNorm follows the last of the 6 layers. The CPE-CLIP decoder wrapper calls the same layers, so the same holds there. Consequences: (1) the unused `self_attn` + `norm1` hold 6 x 16,810,752 = 100,737,024 parameters, so of the 440,029,541 parameters counted as trainable in sequential fine-tuning / distillation-based runs, 339,292,517 receive gradients (state this in Ch. 5, or report both numbers); (2) dropout 0.1 is active in training mode inside the layer (attention dropout of `multihead_attn`, dropout2/3); in the LoRA wrapper the attention dropout is 0 (`layers.py:353`); the prompt-tuning strategy keeps the base model in eval mode, so no dropout there. The VoxTell paper (Sec. 3) also describes only text-query-to-image attention, consistent with this.
- *Training loop* (`training/trainer.py`, `training/optimizer.py`, `data/dataset.py`): batch size 1, one 192³ patch per training volume per epoch (an epoch = N_t iterations, shuffled); 85% of patches centred on a random foreground voxel, otherwise uniform random (zero-padded if the volume is smaller); **no data augmentation**; one text prompt per sample (each task adapter keeps one label); no negative prompts. Loss = BCE (logits) + soft Dice (MONAI `DiceLoss`, sigmoid), weights 1:1. SGD, Nesterov, momentum 0.99, weight decay 3e-5, initial LR 1e-4, polynomial decay with power 1.0 stepped **per iteration** over E·N_t steps (E = 10), restarted for every task (new optimiser per task). `clip_grad_norm_(max_norm=1e9)` is called after `optimizer.step()`: logs the norm only, no clipping. Seeds re-set to 42 at the start of every task (`seed_everything`).
- *Validation.* Each epoch, validation loss (same BCE+Dice) on the 23 validation volumes; the validation dataset is built in `"train"` mode, so each volume contributes **one random 192³ patch (85% foreground-centred), different in every epoch** (the RNG advances across epochs), not the full volume. Best epoch = lowest validation loss. Validation patches are therefore a noisy selection criterion.
- *Selected epochs* (`scripts/selected_epochs.py` → `thesis/tables/selected_epochs.csv`, 2026-10-21): in the 7 best-validation runs (42 tasks) the evaluated epoch is the last one in only 5 tasks (10- and 20-shot fine-tuning); 0/6 in each main-comparison run (fine-tuning, ZSCL-based, CPE-CLIP-based) and in reverse-order fine-tuning. Selected epochs: 8 in 28 of 42 tasks, otherwise 10 (5), 6 (4), 2 (3), 9 (2). The same epochs recur across tasks and strategies. Consistent with the code: the validation dataset's RNG is re-created with seed 42 for every task, so the sequence of foreground/random patch choices repeats each task, and the "best" epoch may reflect which patches were drawn more than model quality (not proven). All LoRA runs: last epoch (10) by construction.
- *Inference.* Crop to non-zero bounding box, z-score, sliding window 192³, 50% overlap (step 0.5), Gaussian weighting σ = 1/8 of patch size (nnU-Net `compute_gaussian`), sigmoid, threshold 0.5, no test-time mirroring (`inference/sliding_window.py`, `evaluation/test.py:122`).
- *Sequential fine-tuning* (`fine_tuning/strategy.py`): base class only; all 440,029,541 image-model parameters trainable; one engine kept across tasks.
- *LoRA (both variants)* (`lora/common/layers.py`, `lora/common/utils.py`): LoRA on the **cross-attention** (`multihead_attn`) of all 6 prompt-decoder layers, query and value projections only; self-attention, encoder and UNet decoder untouched. ΔW = s·B·A with A ∈ R^{r×d} (Kaiming-uniform init), B ∈ R^{d×r} (zero init), **s = α/√r** (rsLoRA-style; `layers.py:42`, the α/r line is commented out); dropout on the LoRA input path only. Trainable params = 2 projections × 6 layers × 2·r·d = 49,152·r (r = 4 → 196,608; r = 1024 → 50,331,648; matches SLURM logs). LoRA attention dropout of the wrapped MHA set to 0.
- *LoRA cost as implemented* (verified 2026-10-21, `lora/common/layers.py:73-110, 183-208`): during training the update is formed as the dense d x d matrix BA in every forward pass (O(d^2 r)) and applied as a second projection (x @ (BA)^T), so the adapted projections cost about twice as much; in eval mode the update is merged into W_0 once (`lora_train(False)` -> `add_lora_data`), so inference costs the same as the pretrained model.
- *Task-specific LoRA* (`lora/task_specific/strategy.py`): `configure_engine` rebuilds the engine from the pretrained checkpoint before **every** task, so each adapter is trained independently from θ_0; there is no sequential dependency between tasks. Evaluation: task i ≤ current stage → adapter of task i; tasks not yet trained → adapter of the current stage; control task → pretrained model without adapter. Config α = 16, dropout 0.05 (s = 8 at r = 4).
- *Shared LoRA* (`lora/shared/strategy.py`): one adapter created once and trained on all tasks in sequence; evaluated with the adapter of the current stage on every task including the control task. Config α = 32, dropout 0.1 in **all** shared-LoRA runs, including the rank ablation, so s = 32/√r changes with r (r = 4: 16; 32: 5.66; 128: 2.83; 256: 2; 512: 1.41; 1024: 1; 2048: 0.71). Source: run `config.yaml` files.
- *Replay* (`strategies/base.py:107-171`): memory initialised before task 1 with round(0.1·19) = 2 AeroPath training volumes, then after each task round(0.1·N_t) volumes of that task (108 → 11 volumes; k = 5/10/20 → 1/1/2) are added; max size 200 (never reached: 2 + 6·11 = 68); memory samples are appended to the current task's training list (each replayed volume gives one patch per epoch with its own prompt). Sampling with Python `random.sample`.
- *ZSCL-based* (`zscl/strategy.py`): teacher = frozen copy of θ_0 (kept on CPU, moved to GPU every iteration). Loss = seg. loss + λ·KL(p_teacher ‖ p_student), λ = 0.01 (config), where p = softmax over all voxels of the dot product between the L2-normalised stage-4 text-guidance vectors (G = 32 vectors of 320 dims, `mask_embeddings[4]`) and the stage-4 **encoder** features (the skip `skips[4]`, 320 channels, 12³; corrected 2026-10-21, `voxtell_model.py:273` returns `skips`), computed on the **current task's** batches. (Verified 2026-10-21: guidance vectors L2-normalised over the 320 channels, encoder features not normalised; one softmax over the 12³ = 1,728 voxels per guidance vector; `F.kl_div(..., reduction='batchmean')`. Note: in VoxTell's forward pass 𝐄_4 is fused with the decoder features at 12³ (after upsampling, concatenation with `skips[4]` and convolution), but ℒ_KD pairs 𝐄_4 with the encoder output `skips[4]`. Gradients of ℒ_KD reach the image encoder (stages 0–4), the prompt decoder and its stage-4 projection, not the UNet decoder.) Weight ensemble: every 10 iterations θ̄ ← θ̄ + (θ − θ̄)/(n+1) (running mean, initialised with θ_0, counter n never reset across tasks); saved to `tasks/<task>/best_model.pt` after each task. **But evaluation loads `tasks/<task>/checkpoints/best_model.pt` (the student's best-validation checkpoint), so the weight ensemble never enters the reported results**, and training continues from the student. Verified: "Model load | ckpt=…/checkpoints/best_model.pt" in `eval.log`. All 440 M parameters trainable.
- *CPE-CLIP-based* (`cpe_clip/model.py`, `cpe_clip/transformer.py`): whole VoxTell frozen (and kept in eval mode); trainable (a) learned prompt tokens G ∈ R^{3×2×2048} (2 tokens appended to the cross-attention memory of the first 3 decoder layers, zero positional encoding, "replacement" mode, Xavier-uniform init; `prompt_init_std` is **unused**), and (b) a meta-net MLP (2d → 2048 → d, GELU) that adds an offset to the text query in those 3 layers from [query; mean of memory]. Params 12,288 + 12,587,008 = 12,599,296 (matches log). Gradient scaling ("balance"): γ_t = max(0.25, 1/t) applied to the token gradients only (not the meta-net). **Inactive in the run**: `_active_task_index` is never set, so γ_t = 1.0 for all six tasks (log: "task_index=1 | alpha_t=1.0000" six times in `voxtell_1779285.out`).

## 3. Limitations and threats to validity (to discuss)

- One seed per configuration; variability can only be reported across the 24 test volumes, not across runs.
- One support set per few-shot setting; no variability across support-set samples.
- (2026-10-22) Few-shot settings reduce the data and the number of updates together (k · E: 50/100/200 vs 1,080 per task). Only k = 5 gets an equal-updates run, and only for three strategies; for k = 10/20, distillation-based and prompt tuning, the two effects stay confounded. State this where objective 3 is answered.
- (2026-10-22) One shared training configuration for all strategies (no per-strategy tuning of learning rate or epochs): results compare strategies under this budget, not at their best settings. LoRA is sensitive to both (Only-Patellar diagnosis runs).
- (2026-10-22) Bootstrap intervals (single and paired differences) reflect test-volume sampling only; they are unadjusted for the number of comparisons.
- No joint-training upper bound; no intransigence measure.
- ZSCL and CPE-CLIP: no reverse-order or few-shot runs. TIL-LoRA rank ablation only r = 4 and r = 8 on 6 tasks.
- Control task: one dataset, one large high-contrast structure, 4 test volumes.
- TIL-LoRA needs the task identity at inference; its 0 forgetting and 0 control-task drop follow from that.
- Replay runs train on the control task, so their control-task drop is not comparable with the other strategies.
- ZSCL implementation differs from the original (no reference dataset).
- Code version per run not recorded.
- (Found 2026-10-21, from `code/`) Distillation-based (formerly "ZSCL-based"): weight ensemble computed but not used in evaluation; snapshots deleted, so not recoverable. CPE-CLIP-based: per-task gradient scaling never activated (γ_t = 1). LoRA strategies evaluated at the last epoch, the others at the best-validation epoch. Validation loss computed on one random patch per volume, different each epoch. Task-specific and shared LoRA use different α and dropout. Shared-LoRA rank ablation changes s = α/√r together with r. No data augmentation in fine-tuning. Each needs a decision by the author (describe as is, rename, or rerun).
- SKM-TEA: own random split instead of the official 86/33/36 split (the official test patients are mixed into all three splits); results are not comparable with SKM-TEA benchmark numbers.
- SKM-TEA NIfTI files have an identity affine. **Corrected 2026-10-24:** VoxTell's own plans (`code/models/voxtell_v1.1/plans.json`, official HF repo mrokuss/VoxTell) use no resampling (`nnUNetResEncUNetLPlans_noResampling_3d_fullres`, no target spacing) and ZScoreNormalization for all inputs incl. CT, with `NibabelIOWithReorient`; our pipeline does the same. So the identity affine does not change the scale of the input (the network sees voxel grids either way); it removes only the orientation (stored axis order; 18 of 155 scans L-R reversed). Earlier wording 'treated as 1 mm isotropic / different scales' was misleading and is removed from Ch. 4 and Ch. 7.
- Echo 1 only; the second qDESS echo (used by the annotators) is not given to the model.
- Each SKM-TEA scan was labelled by one annotator; no inter-rater information.
- Lung labels of AeroPath: origin not documented in the paper (manual or automatic?).
